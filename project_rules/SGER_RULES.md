# SGER-CasMVSNet 项目整体规则

本文是 SGER-CasMVSNet 项目的长期规则，适用于网络设计、源码修改、损失设计、训练、推理、评估和研究报告。所有后续改进必须遵循。具体实验的超参数、训练阶段、数值目标和操作命令应维护在各自实验文件中，不作为项目永久约束。

## 1. 研究主体与改进目标

1. 正式名称必须使用 **SGER-CasMVSNet（自几何与边缘细化残差-CasMVSNet网络）**。
2. SGER 是核心研究贡献，承担自几何、边缘感知和残差细化；CasMVSNet 承担多视图匹配、级联搜索和原始深度估计。
3. 每项改进必须明确改善哪个 SGER 组件、针对什么可观测问题，以及用什么指标验证。不能仅以主干指标改善替代 SGER 贡献证明。
4. raw 路径作为受保护主干、对照或监督来源保留。若 refined 差于 raw，必须诊断残差方向、门控、几何线索、不确定性或优化问题；不得把删除或长期绕过 SGER 当作最终研究方案。

## 2. 活动源码与数据契约

1. 修改前必须确认实际导入链：`models/cas_mvsnet.py` → `models/module.py` 和 `models/sger_refinement.py`。不得将 `module1.py` 或 `train1.py` 的修改误认为已改变活动训练路径。
2. 保持输入契约：图像为 `(B,N,3,H,W)`，投影矩阵按 stage 提供，初始深度假设由 `depth_values` 提供；深度图为 `(B,H,W)`，预测法线为 `(B,3,H,W)`。
3. 图像、特征、深度、掩码、置信度与相机内参必须对应同一 stage 的分辨率。几何修改必须检查内参缩放、坐标系、有效像素和批次行为。
4. 保持 raw、refined、未门控残差、有效残差和置信度的语义清晰。SGER 开启时，`depth_raw` 是当前 stage 的细化前深度，`depth_refined` 是细化后深度，`depth` 指向细化结果。
5. 原有 `refine=True` 的 `RefineNet` 与 SGER 是不同路径，不得混用名称或据其默认关闭推断 SGER 状态。训练、测试必须显式记录 SGER 开关和配置。

## 3. 网络设计与优化边界

1. 网络改进必须保留多视图深度估计与 SGER 自几何、边缘感知、残差细化之间的明确职责。新增模块应说明输入、输出、作用位置、计算成本及其对 SGER 的帮助。
2. 单阶段细化、多阶段细化、模块共享和级联反馈均可作为研究方向，但必须明确改变了哪些搜索中心和监督路径，并提供对应消融。不得把某一现有模式固化为唯一允许的最终结构。
3. raw 与 refined 的监督职责必须明确。主干应保有有效的深度监督，SGER 应获得可学习的细化信号；不得因冻结、detach、损失调度或优化器遗漏使目标分支长期无法学习。
4. 必须显式设计各项损失允许更新的模块。梯度隔离、联合训练、分阶段训练均须根据研究假设选择，不能将某次实验的隔离策略或学习率设为项目永久要求。
5. 改动共享特征、细化加法、级联反馈或损失连接后，必须验证实际梯度路径与设计一致。要求隔离的路径不得存在意外梯度；要求学习的路径应在损失有效激活时产生有限梯度。
6. 梯度审计必须区分无梯度、零梯度、非有限梯度和参数未被优化器覆盖，并说明初始化、有效掩码及训练调度的影响。数值容差应按精度与审计条件记录，不能仅以某个固定阈值判断所有实现。
7. 如联合优化导致 raw 退化，必须分析损失冲突、梯度尺度及学习率等原因，同时评估 SGER 的实际收益。不得用损害对照质量的方式制造 refined 相对优势。

## 4. 残差、门控与监督

1. 残差必须有明确的单位、方向、尺度和幅度控制机制，避免无约束修正破坏有效深度。具体参数化、限幅方式和调度可以改进，但必须验证数值稳定性及细化收益。
2. 使用门控时必须区分残差提案、门控权重与最终有效残差。初始化应控制初始扰动，同时保证残差和门控能够逐步学习；具体初始化方式须验证。
3. 残差监督必须与纠正 raw 误差的方向一致，尺度与预测参数化一致。采用收益门控时，其监督或验证必须反映实际细化收益，不能把高置信度或非边缘直接等同于细化有收益。
4. GT 只能用于训练监督和评估，不能进入推理几何线索或门控输入。
5. 法线自洽、平滑度、曲率连续性只说明几何性质，不能单独证明深度准确。几何约束必须考虑有效区域、边缘和可靠性，避免跨真实边界过度平滑。
6. 损失权重、残差幅度 warm-up 和残差目标/收益门控的独立调度必须分别记录实际生效值；不能仅根据命令行基础权重判断训练状态。

## 5. 先诊断，再做单变量改进

1. 完整训练前，先验证所提问题的证据：逐项梯度、残差提案、门控分布、有效残差和有效损失权重。
2. 有效残差接近零时，必须区分提案接近零、门控接近零、两者同时缩小，以及 beta、恢复状态或日志错误。必要时检查逐像素乘积和分布，不能只凭均值断定塌缩。
3. `gate_precision` 与 `gate_recall` 同时为零不能直接认定门控完全关闭；必须检查预测正样本、目标正样本和真阳性数量。
4. 每轮实验围绕一个核心假设改变一个主要因素。不得同时更改主干学习率、残差权重、门控机制、残差范围和融合阈值后归因于其中一项。
5. 必须将源码状态、研究假设、运行证据和原因推断分开记录。结构存在或测试通过不等于取得重建收益；相关性不能直接当作因果证明。

## 6. 必须记录的诊断指标

每个 epoch 记录 raw/refined 质量、细化幅度及实际生效损失权重。对当前残差与门控结构，还应记录以下诊断项；结构演进后可使用语义等价的指标，并同步说明映射：

- `sger_residual_scale`、残差目标与收益门控的有效损失权重。
- 各细化 stage 的 `raw_abs_error`、`refined_abs_error`、`raw_to_refined_error_delta`；其中 delta 为 raw 误差减 refined 误差，正值表示改善。
- `mean_abs_raw_residual`、`mean_abs_depth_residual`、`residual_sign_accuracy`。
- `benefit_gate_mean`、`benefit_target_positive_ratio`、`gate_precision`、`gate_recall`。
- `gate_on_improved_mean`、`gate_on_worsened_mean`、改善与恶化像素比例。
- 残差目标损失、收益门控损失及相关几何指标。

指标必须标明训练/验证集、stage、有效掩码及聚合方式。缺失指标应补齐或标注未采集，不得当作零值或推断性结果。

## 7. raw/refined 公平评估

1. 至少比较同一 checkpoint 的 refined depth + raw confidence 与 raw depth + raw confidence。若引入置信度校准，另增 refined depth + calibrated confidence，独立评估校准贡献。
2. 深度细化与置信度校准必须分别消融，不得将校准带来的提升全部归因于深度细化。所有结果必须明确标注深度源与置信度源，分组名称不能代替配置记录。
3. 各组使用独立输出目录，并保持场景、图像尺寸、视图数、深度采样、融合阈值和评估程序一致。refined 稳定优于 raw 前不进行融合阈值搜索。
4. 全阶段 SGER 的最终 `depth_raw` 已可能受前级细化搜索中心影响，不能称为完全独立的原始 CasMVSNet 基线；需要另外关闭 SGER 的对照才能评估整条级联贡献。
5. 报告逐场景及汇总 Acc.、Comp.、Overall，并记录点数、光度/几何/最终掩码通过率及视图一致性计数分布。缺失的统计须明确说明。
6. 不能仅凭训练 depth loss、改善像素比例或单项 DTU 指标选择“最佳”结论。同一协议下 refined 的 Acc.、Comp.、Overall 全部低于 raw，才满足本项目的最终贡献标准；稳定性还需跨 checkpoint 或重复实验验证。

## 8. 验证、报告与维护

1. 结构、几何、损失或梯度修改后，运行与修改相关的最小有效验证；优先利用 `tests/` 中已有测试及 `gradient_audit.py`。梯度审计不应执行优化器更新或改写输入 checkpoint。
2. 完整训练前确认输出形状、有限性、残差上界、参数优化器覆盖和期望梯度路径。静态阅读或测试通过不能代替真实 DTU 实验。
3. 每次实验记录问题、假设、唯一主要改动、基线、完整命令、种子、数据划分、checkpoint 来源、epoch 编号、实际生效配置、评估分组和结果；恢复训练还需记录优化器及调度状态。
4. 历史实验文件保留原始记录。后续纠正应注明原因与证据，不得覆盖历史结果来适配当前结论。源码、规则与历史说明不一致时，明确指出差异并同步维护适用文档。
5. 本规则是项目长期维护入口。改变研究约束或实验口径时更新本文及相关实验记录，避免复制多份互相冲突的规则。数据、checkpoint、日志和生成点云不得作为源码提交。
