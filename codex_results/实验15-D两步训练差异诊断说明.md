## 执行命令

2026-09-16新增冻结主干定位模式。当前下一步执行下面完整一行：

```bash

```

此模式冻结主干参数，并将主干模块置于eval模式以固定BN状态；SGER模块（包括末级法线头）保持train模式。优化器仍严格恢复原分组及动量，冻结参数的梯度为None，使Adam跳过其更新。每步核验主干参数、缓冲区和优化器状态相对初始化完全一致，同时记录SGER非零梯度及实际变化的参数。没有修改正式训练入口。

输出目录为 `outputs/experiment15_d/diagnose_frozen_时间戳/`。除原有比较外，`summary.json` 增加 `freeze_backbone` 和 `frozen_backbone_checks`。检查三组每步的 `passed`，以及SGER变化记录；再查看两组对照的 `first_protected_difference` 是否为空。raw一致指相同输入下三组对照一致，不要求两个不同batch之间raw相同。

冻结主干还改变了主干BN运行模式，因此该实验是定位用对照，不能当作原联合训练的精度结论，也不能据成功运行断言所有非确定性均已排除。如果严格模式仍报错，应继续保留并分析报错。

## 结果字段

先看 `summary.json`：

- `legacy_repeat` 是旧BCE重复对照，`stable` 是新旧BCE对照。
- `first_difference` 为首次出现差异的阶段及该阶段按名称排序的首个差异项。
- `first_protected_difference` 只追踪主干、输入和随机状态，排除新旧BCE预期的SGER变化。

阶段按初始化、step0验证、每步输入、前向、反向、更新排列。阶段内张量按名称排序，不代表算子执行先后。

详细JSON在 `legacy_repeat/`、`stable/`，记录形状、类型、有限性、最大/平均绝对差和不同元素比例，区分None与零梯度。比较各stage raw深度/置信度、SGER输出、BN缓冲区、参数、梯度及按参数名称展开的优化器状态；初始化优化器分组超参数也参与比较。

`reference_snapshots/` 保存基准CPU张量，文件可能较大。`manifest.json` 保存配置、源码和checkpoint哈希、环境及执行状态。失败或中断时保留已生成记录。

## 判断顺序

1. 旧BCE重复组也有主干差异：优先定位同模式可重复性，但不自动排除新损失问题。
2. 输入或初始化状态首先不同：检查数据、随机状态和恢复配置。
3. 输入及前向相同，反向首先不同：检查损失连接和反向计算可重复性。
4. 主干梯度一致但更新后参数不同：检查优化器状态、分组及更新过程。
5. 新旧BCE的SGER梯度、参数和后续refined输出允许不同。哈希或逐位不同不是精度退化证据，要结合差异幅度与旧BCE重复对照判断。

脚本打印 `Diagnostic completed` 仅表示采集完成，不表示审计PASS，也不自动诊断梯度泄漏或训练收益。

进一步定位可重复性时，可另开严格确定性检查：

```bash
CUBLAS_WORKSPACE_CONFIG=:4096:8 OMP_NUM_THREADS=1 PYTHONPATH=. python -u experiment15_d_diagnose.py --strict_determinism
```

此选项启用PyTorch严格确定性检查。遇到不支持的算子或缺少相应环境配置时会报错，保留报错用于定位，不将其视为BCE审计失败。默认运行保持原探针的随机种子及cuDNN设置。
