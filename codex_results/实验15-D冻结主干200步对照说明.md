# 实验15-D：冻结主干200步新旧BCE对照

2026-09-19。研究主体：**SGER-CasMVSNet（自几何与边缘细化残差-CasMVSNet网络）**。

本次仅完成代码及CPU验证，真实DTU运行由用户执行。此模式是带参数更新的局部训练对照，不是无更新的梯度审计。输入checkpoint只读；实验快照保存到新目录。

## 研究问题与边界

验证稳定BCE是否改善SGER收益门控学习，并增加同一主干输出上的raw→refined收益。唯一组间主要变量是BCE计算方式。冻结主干及主干BN处于eval对三组同时生效；这是独立实验，不能代替原联合训练或证明解冻状态无梯度泄漏。

入口为 `experiment15_d_probe.py --freeze_backbone`，实现位于 `experiment15_d_frozen_probe.py`，复用两步诊断中的冻结、训练模式恢复和状态检查。原探针不带冻结选项时仍执行历史两组模式。

## 固定配置

- 从 `outputs/experiment15_d/short_train/sample_manifest.json` 读取Epoch15 checkpoint、训练参数、400个训练样本及6个验证样本；验证checkpoint哈希、样本数量和元数据。当前默认checkpoint是 `checkpoints/experiment15_b_backbone_lr1/model_000015.ckpt`。
- 顺序执行 `legacy_reference`、`legacy_repeat`、`stable`；每组重新初始化随机状态，加载同一checkpoint及Adam分组、学习率和动量。
- 每组200步、batch size 2，保持ReLU、残差范围和损失权重；固定Epoch15有效调度，不推进epoch或学习率调度器。实际有效权重和尺度写入 `manifest.json` 的 `effective_case`。
- 主干参数冻结、主干模块eval；SGER及末级法线头保持train。验证后恢复这一模式。
- 第0、25、50、100、200步验证并保存模型/优化器快照，验证集及顺序保持一致。
- 保留原探针对25对已通过BCE机制审计的文件哈希及活动源码哈希检查。源码或证据不匹配时停止，不能把旧PASS当作新代码证据。

```bash

```

## 检查与输出

首先读取 `summary.json`：

- `status=completed`、`checks_passed=true`、三组 `completed_steps=200` 才表示本次对照检查全部完成。
- `comparisons.legacy_repeat` 的所有阶段应 `exact=true`。比较覆盖输入、随机状态、各stage raw/置信度、SGER输出、总损失、梯度、模型及优化器状态。
- `comparisons.stable` 允许SGER和损失差异，但所有 `first_protected_difference` 必须为null；初始化必须完全相同。
- `validation` 给出5个验证节点的三组stage3指标。

每组目录包含 `metrics.json`、`optimizer_mapping.json`、`module_training.json`、5个checkpoint及 `fingerprints/`。每步检查主干参数、缓冲区和优化器状态相对初始化不变、主干梯度为None；要求SGER至少存在非零梯度和相对初始化的参数变化，并记录具体参数名。这不代表每个SGER参数每步都更新。检查输出形状、残差幅度上界、张量有限性和可训练参数的优化器覆盖。

采用带dtype/shape的SHA256指纹比较完整张量，减少200步完整快照的磁盘开销；可定位首个不同字段，但不提供张量差值幅度。不同样本之间的raw无需相同，检查的是相同样本在配对组之间一致。数据元数据与历史清单比对，实际输入张量在本次三组间比对；没有对数据文件与历史版本逐字节比对。

若失败或Ctrl-C中断，`manifest.json`、`summary.json` 标记failed/interrupted及错误，`checks_passed` 保持false。已写记录保留，不支持从中断目录恢复，重新运行请用新目录。CUDA、历史证据或checkpoint预检失败可能发生在创建结果目录之前。

## 指标口径与判断

stage3训练逐batch记录，验证按 `mask > 0.5` 的有效像素总数聚合，而非batch均值平均。记录raw/refined绝对误差、raw减refined的误差差值、残差提案/有效残差幅度、方向准确率、门控均值、收益目标比例、precision/recall、改善/恶化比例和对应门控均值。损失及额外损失指标保留在逐batch记录，不与全局像素加权指标混用。

- 正的 `raw_to_refined_error_delta` 表示该组refined优于raw；还需比较stable是否比legacy_reference取得更大收益。
- `residual_sign_accuracy` 在全部有效像素上统计 `proposal * (GT - raw) > 0`；零提案或raw恰等于GT不算方向正确。
- precision/recall由合并后的TP、预测正样本和目标正样本计数计算。分母为0时记null，不伪装成测得的0。
- `gate_on_improved_mean` / `gate_on_worsened_mean` 按最终refined误差与raw误差比较分组；收益门控目标仍基于未门控提案及记录的margin。
- 区域无有效像素时对应均值为null。额外保留计数及求和量，支持复核聚合。

若stable在多个节点持续提高细化收益，再进入正式训练和同checkpoint的raw/refined公平重建评估；若差异很小，仅说明当前Epoch15起点影响有限。门控指标改善不能替代深度误差及DTU Acc./Comp./Overall证据。本实验未执行融合或DTU点云评估。
