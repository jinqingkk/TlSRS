## 1. 为什么做15-D

15-C 已给出以下事实：

| 已有证据 | 对15-D的含义 |
|---|---|
| Epoch9/12 的 ReLU 残差主体梯度为零；LeakyReLU 可以恢复主体梯度 | 残差激活问题已定位，但不是本轮主要变量 |
| Epoch9/12 全部有效像素的最终门控低于1e-6 | 当前 BCE 的概率硬截断可能阻断门控学习 |
| 固定 LeakyReLU 后，Epoch9/12 收益正标签率为10.7755%/19.0527%，门控专属参数梯度仍为零 | 存在“有正收益监督、却无法更新门控”的真实压力样本 |
| Epoch15 原 ReLU 已有细化收益；直接换 LeakyReLU 使平均收益减少约54.7% | 本轮主要对照保留 ReLU，不默认替换最终激活 |

当前活动 `models/module.py::balanced_binary_cross_entropy` 先执行 `prediction.clamp(1e-6, 1-1e-6)` 再计算 BCE。截断区外对输入概率的导数为零；概率很低时，即使正标签使损失很大，梯度也可能无法传回门控参数。

**核心假设：**在保持最终门控概率含义、监督标签、类别平衡与优化边界的条件下，稳定计算收益 BCE，可以恢复可学习像素在饱和状态下方向正确的梯度，并保持正常概率区间的原有行为。

本轮先证明数值与梯度机制；训练收益必须通过后续参数更新和独立验证集观察，不能由梯度恢复直接推出。

## 2. 本轮允许改变什么

| 项目 | 规定 |
|---|---|
| A组 | 原概率 clamp + balanced BCE，命名 `legacy_clamp` |
| B组 | 从原始门控 logits 和几何权重稳定计算同一收益概率的 BCE，暂命名 `stable_logprob` |
| 唯一主要变量 | 上述门控 BCE 数值实现 |
| 前向网络 | 保留两区域门控、几何权重、原始/细化深度和残差计算 |
| 监督 | 保留GT有效掩码、收益标签生成、margin、正负类别平衡及归一化方式 |
| 其他配置 | 保留损失权重、残差上界、初始化、学习率分组、warm-up与梯度隔离设计 |
| 兼容性 | 旧checkpoint的参数键和形状不变；模式需显式记录，避免静默切换 |

严禁在同一A/B对照中同时改变激活、margin、几何权重下界、残差目标权重、门控初始化或融合阈值。也不能仅通过减小clamp阈值、强制开门或替换为任一单分支BCE，就声称解决了原混合门控的数值问题。

## 3. 实现任务与概率语义

当前活动链为 `models/cas_mvsnet.py` → `models/module.py`、`models/sger_refinement.py`。不能修改 `module1.py` 后将其当作活动路径。

当前 `DualRegionGate` 的计算为：

```text
z_a = gate_a(fused_features)
z_b = gate_b(fused_features)
p = clamp((region_a * sigmoid(z_a) + weight_b * sigmoid(z_b)) * valid_mask, 0, 1)
```

实施前验证当前区域构造保证的权重范围、区域互斥性及零权重条件。稳定损失必须表达这个最终概率；不能把 `z_a`、`z_b` 或二者的线性组合直接当作最终门控logit，也不能将已经舍入为0/1的概率转回logit来补救。

建议从原始分支logits和实际几何权重构造稳定的 `log(p)` 与 `log(1-p)`，使用兼容现有PyTorch的 `logsigmoid`、`softplus`、`logsumexp` 等运算。目标是去除收益损失中的人工概率硬截断，同时保持原前向门控张量及其用途。具体公式须先通过第4节的独立数值验证，再接入训练。

实施清单：

1. `models/sger_refinement.py`：向损失路径提供未detach的门控logits或稳定对数概率及必要权重；保持原门控前向公式，避免重复执行门控网络。
2. `models/cas_mvsnet.py`：将所需附加张量传递到对应stage输出，保持stage分辨率和训练图连接。保持原有feature/depth/confidence的隔离边界。
3. `models/module.py`：保留旧实现，增加稳定实现与显式选择；收益标签继续detach，类别平衡继续依据相同GT有效像素的标签比例计算。单一类别和空掩码行为也必须覆盖。
4. `gradient_audit.py`、`gradient_audit_utils.py`及相关统计工具：增加“固定激活、新旧BCE”配对审计，恢复相同参数、BN和随机数状态，补充logit梯度及前向不变性检查。不能把原 `--activation_ab` 当作BCE对照开关。
5. `train.py`：审计通过后再接入同一模式选择，并记录checkpoint配置和实际生效权重。推理仍使用原前向公式；如附加输出影响接口，验证 `test.py` 兼容性。
6. 新增有针对性的数值及审计测试，复用现有合成输入和隔离检查。新接口必须在记录命令前完成 `--help` 和参数传递核验。

**结构零值的处理边界：**有限logit的sigmoid数值下溢，与几何系数严格为零造成的门控不可达，不是同一种情况。对于最终概率被结构固定为0而GT标签为1的像素，精确BCE本身为无穷，单靠数值重写无法同时保证等价、有限且可学习。必须统计并显式报告该条件；不得暗改有效掩码、类别平衡或权重下界。若真实有效区域出现该冲突，单独设计后续实验，本轮不能虚报数值修复通过。空掩码须在危险对数运算前安全返回可反传的零损失。

## 4. 第一阶段：合成输入验证

先在CPU完成；CUDA真实审计前至少复核关键极端案例。以float64作为参考、float32作为实际训练精度，不引入AMP作为额外变量。

| 验证项目 | 构造 | 必须观察到的结果 |
|---|---|---|
| 正常区间等价性 | 最终p位于0.001–0.999；覆盖A区、B区及不同非零几何权重 | 新旧损失及对logits的梯度接近，类别平衡与归一化一致 |
| 极低门控、正标签 | 活动分支logit取-20、-80、-120，几何系数非零 | 新损失有限，活动logit梯度为负；负梯度方向使门控增大；旧实现的截断阻断可复现 |
| 极高门控、负标签 | 使用可达到接近1概率的权重配置，logit取20、80、120 | 新损失有限，活动logit梯度为正，下降方向使门控减小 |
| 已正确的饱和预测 | 极低门控配负标签、极高门控配正标签 | 梯度允许极小或在实际精度下为零，不得强制开门或要求所有样本都有大梯度 |
| 几何调制 | weight_b取1、0.5、1e-4；检查分支系数为0的情况 | 最终概率上界和梯度符合原公式；未激活分支梯度可以为零 |
| 标签分布 | 全正、全负、混合、不平衡标签 | 保持原单类回退行为和混合类别权重；不能让单类分支损失意外归零 |
| 掩码 | 全有效、部分有效、空掩码、结构零冲突 | 无效像素无监督梯度，空掩码安全；结构不可达明确标记 |
| 形状 | B=1和B=2，不同小分辨率 | 输出、掩码、logits及权重按像素对齐，无错误广播 |
| 梯度参考 | 可学习、非边界样本上的float64参考/有限差分 | autograd梯度与独立参考一致，不仅检查“非零” |

正常区间建议初始验收容差：float32 `atol=1e-6, rtol=1e-4`；float64 `atol=1e-10, rtol=1e-7`，同时适用于损失与对应梯度比较。若因归约精度需调整，记录误差分布和理由，不得仅放宽容差以掩盖公式不一致。极端区间用稳定参考和梯度方向验收，不能要求与旧截断后的损失相等。

## 5. 第二阶段：真实checkpoint配对审计

### 5.1 固定数据及分组

复用15-C的 `model_000009.ckpt`、`model_000012.ckpt`、`model_000015.ckpt`，来自 `checkpoints/experiment15_b_backbone_lr1/`。epoch按文件内零起始编号记录。

固定DTU train split、seed=1、Batch=2、批次0–4、3视图、48/32/8采样、4/2/1区间、Stage3 512×640、SGER-lite、主干未冻结、train模式及num_workers=0。其余完整arguments以 `outputs/experiment15_c/activation_ab_verified_summary_20260913.json` 中对应记录为基准，逐项存入15-D元数据。

| 组别 | 固定末端激活 | Epoch | A/B变量 | 目的 |
|---|---|---|---|---|
| 主要对照 | ReLU | 9、12、15 | 旧BCE/稳定BCE | 验证原模型兼容性与Epoch15正常门控行为 |
| 补充压力对照 | LeakyReLU，slope=0.01 | 9、12 | 旧BCE/稳定BCE | 利用已有正收益标签验证饱和门控的学习恢复 |

每组5个Batch，共25个新旧BCE配对、50份变体报告、25份比较报告。若保留现有15个case，则共750个case；新增诊断case单独计数。补充对照不证明LeakyReLU适合作为最终激活，不允许把“ReLU+旧BCE”与“LeakyReLU+新BCE”的差异归因于BCE。

### 5.2 运行顺序

1. 先跑Epoch9、Batch0、固定LeakyReLU的新旧BCE配对，验证真实正标签上的门控学习通路。
2. 再跑Epoch15、Batch0、固定ReLU配对，验证活跃模型的正常行为。
3. 两个试运行均满足对应验收条件后补齐上述25个配对；避免在错误实现上批量消耗GPU时间。
4. 每个case及每个变体恢复相同模型参数、BN缓冲和随机数状态；审计不执行optimizer.step，不写回输入checkpoint。
5. 旧BCE出现15-C已知门控梯度错误时，仍完成稳定BCE和比较文件；保留错误，不把整个任务误判为未生成结果。

### 5.3 必须验证的内容

| 项目 | 验证方式与通过条件 |
|---|---|
| 前向不变 | 同一case比较raw depth、raw confidence、未门控残差、最终门控、有效残差及refined depth的逐像素最大绝对差；默认要求均严格为0 |
| 输入和标签不变 | 样本元数据、GT有效掩码、收益标签、正负计数、几何权重及beta一致；比较标签逐像素差，不只比较均值 |
| BCE变化位置 | 正常区间差异符合第4节容差；饱和区允许损失改变，但必须对应稳定参考与正确梯度 |
| 门控学习恢复 | `gate_benefit_only` 中，含可学习正标签的饱和样本存在有限且方向正确的活动logit梯度，并到达相关门控参数 |
| 参数梯度 | 分别记录无梯度、零梯度、非有限梯度、梯度L2/RMS及优化器遗漏；不能仅汇总一个总范数 |
| 优化边界 | `gate_benefit_only` 不更新FeatureNet和CostRegNet，收益标签detach使残差头参数不经标签回传；末级normal head和SGER特征投影可经门控输入获得梯度，不误报为主干泄漏 |
| 其余case回归 | 保留raw_only、refined_only、residual_target_only、full_schedule/full_forced及既有几何case，确保未引入额外连接；full_schedule本来允许主干深度监督 |
| 残差安全 | 提案和有效残差有限且不超过各case记录上界；沿用15-C复核容差1e-6，记录实际精度 |
| 配置与恢复 | 记录旧权重键匹配、实际BCE模式、实际激活、seed、batch索引及所有有效权重；审计优化器只用于覆盖检查，不代表恢复历史动量 |

对于主干隔离，沿用现有审计容差1e-8并报告实际范数，目标仍为严格零。只有目标case确有非零SGER学习信号时，零主干梯度才构成有意义的隔离证据之一。

**早期ReLU不能用“门控是否打开”验收：**15-C中这组没有超过margin的正标签。旧门控已很低，新BCE对负标签的正确梯度本就很小；允许出现正常的极小梯度，必须结合标签、权重和结构可学习性解释，而不是降低全局审计标准。关键恢复证据来自固定LeakyReLU的Epoch9/12正标签压力组。

同理，若稳定logit梯度已恢复而某门控参数仍为零，应继续查该门控网络内部激活或共享输入，不能直接判定BCE已解决整条参数学习通路。

### 5.4 必须输出的诊断指标

- 概率与几何：两分支logits、sigmoid和最终门控的min/max/mean及分位数，低于1e-6与高于1-1e-6的计数/比例，结构零权重计数、结构不可达正标签计数。
- 监督与梯度：有效/正/负标签计数，类别权重，旧/新BCE，活动分支logit梯度方向，门控A/B、normal head、SGER特征投影、残差头和主干参数梯度及优化器覆盖。
- 细化：raw/refined平均绝对误差与差值，平均绝对提案/有效残差，提案收益，方向准确率，改善/恶化比例，gate_on_improved/worsened。
- 门控选择：预测正样本、目标正样本和真阳性计数，precision/recall。分母为0时标记无定义；若兼容旧日志输出0，同时保留分母计数。
- 调度：beta、残差目标和收益门控的实际有效权重。full_schedule在Epoch9的beta/收益门控权重为0.75/0.0375，在Epoch12/15为1/0.05；残差目标有效权重均为0.05。专属case权重和强制调度另记。

统计均标明Stage3、GT mask>0.5及train模式。跨Batch均值按有效像素加权；precision/recall合并计数计算；分位数不直接平均；方向准确率只有保存对应分母后才能精确池化。样本仍限于scan2的两个参考视角，不能冒充跨场景泛化。

## 6. 第三阶段：条件满足后做短程训练

**进入条件：**合成数值验证通过；真实压力组恢复门控参数学习信号；前向不变、正常区间兼容和梯度隔离均通过。任一不满足，留在机制诊断阶段，先定位失败项。

建议先进行一个明确标注为“局部训练探针”的对照：

| 项目 | 初始方案 |
|---|---|
| 起点 | 两组均从Epoch15同一checkpoint开始，保留ReLU，以已有活跃残差检验正常学习行为 |
| 更新步数 | 每组200步，在0/50/100/200步保存指标和独立快照；这是预设诊断预算，不是精度目标 |
| 训练数据 | 从同一DTU train split按固定种子生成相同顺序，不只反复拟合审计的5个Batch；保存实际样本索引 |
| 验证数据 | 从DTU val split预先选定固定样本，至少包含3个scan，各2个参考视角，固定光照；先核验数据可用并保存精确清单，不能看结果后挑选 |
| 优化器 | 优先将同一checkpoint优化器状态恢复到两组，并逐项核对参数映射、动量及各组实际学习率；不能一组恢复、一组重置 |
| 无可用优化器状态时 | 两组统一新建优化器，明确记录为“重置优化器的局部训练探针”；在执行前固定完整优化器配置，不将其称为原训练无缝续跑 |
| 调度 | 此200步探针固定Epoch15的beta及有效损失权重；两组学习率固定为共同选定的起始状态，避免在探针内另引入调度差异 |
| 模式 | 训练用train模式，独立验证用eval模式；记录BN处理和实际batch size，两组一致 |
| 唯一差异 | legacy_clamp / stable_logprob |

重点观察：门控是否保持有限且可学习，正收益像素与有害像素能否得到区别处理，验证集上的SGER细化收益是否改善，raw是否退化，以及效果是否只出现在训练样本。

每个保存点比较两组各自的raw和refined，报告四项误差及两组各自的Δ。SGER-lite主干隔离成立时还应核查两组raw轨迹是否一致；发现差异先查梯度、BN和随机数恢复，不能通过降低raw质量制造Δ优势。

Epoch15本来不处于早期全局饱和状态，因此这个探针主要检验兼容性和副作用；即使新旧接近，也不能否定已证明的极端区间数值修复。若需验证“饱和checkpoint经训练恢复”，再单独建立两组激活都固定为LeakyReLU的早期checkpoint训练对照，不能与主要ReLU组混合归因。

200步不足以证明稳定提升。只有独立验证显示值得继续，才扩展到更多步数、跨scan及重复种子；未见提升则记录“数值修复通过、收益未证实”，继续诊断残差方向和门控选择，不据此移除SGER。

审计执行器内部为GPU子进程设置OMP_NUM_THREADS=1、PYTHONPATH=.，记录展开后的完整命令；每个case均恢复参数、BN和CPU/CUDA随机数状态。可用 `--phase pilots`只运行两个试点。重复执行仅复用当前活动审计源码哈希及输出哈希都匹配的已验证结果。

稳定公式利用当前区域互斥关系，将每个有效像素的最终概率写成 `p=w*sigmoid(z)`，保持原前向概率不变：正标签为 `softplus(-z)-log(w)`；负标签在w=1时为 `softplus(z)`，在0<w<1时为 `-log1p(-exp(log(w)+logsigmoid(z)))`。结构零权重的负标签损失为0，结构零权重的正标签显式报错。没有改变类别平衡和归一化。

初版对缩放负标签使用logsumexp计算补概率，在极低概率时出现约1e-10的负损失舍入误差，已换为上述log1p公式，并增加非负微小损失回归测试。初版试点保存在 `outputs/experiment15_d/pre_revision_logsumexp/`，不并入最终25个配对。

稳定BCE直接对原始logits建立损失路径；最终benefit_gate张量是其同源的前向分支。因此gate_benefit_only下，不能仅凭benefit_gate.grad为零判定新损失断开，必须检查新记录的logit梯度和门控参数梯度。

局部训练探针预先固定的验证dataset indices为0、7、343、350、686、693，对应scan3/5/17、各参考视角0/1、光照0。已实际加载核验。Epoch15的SGER与backbone两个优化器组均保存lr=0.000125；探针将恢复这个实际状态，不用审计命令中的backbone_lr_scale=0.1重写历史学习率。原checkpoint没有参数名映射，恢复采用现有分组与参数顺序，并逐项校验状态张量形状和值；这是已核验的恢复方式，不代表重建了历史训练源码。
