# 实验12分析：实验10–12对比与 SGER-CasMVSNet 下一步优化方向

## 1. 分析范围与评价口径

本文依据 `codex_results/实验结果.docx` 中记录的训练指标、DTU评价结果和点云数量，对实验10、实验11和实验12进行统一分析。

三个实验的结构边界如下：

- **实验10：全阶段 SGER。** Stage1、Stage2、Stage3均运行 NormalHead和SGERBlock，前一阶段的refined depth还会成为后一阶段深度采样中心。
- **实验11：Stage3-only SGER-Lite。** Stage1和Stage2保持raw CasMVSNet路径，仅在Stage3预测法线并细化深度；最大残差比例为0.5。
- **实验12：从零训练的Stage3-only SGER-Lite。** 保持实验11的Stage3-only结构，最大残差比例降为0.25，并加入gate稀疏损失和safe-refine损失。实际训练参数为：

```text
sger_max_residual_ratio=0.25
raw_depth_loss_weight=1.0
refined_depth_loss_weight=1.0
residual_loss_weight=0.01
gate_loss_weight=0.001
safe_refine_loss_weight=0.1
safe_refine_margin=0
freeze_backbone_epochs=0
backbone_lr_scale=1.0
```

因此，实验12 Epoch 0–6的异常不能解释为“冻结了随机初始化主干”；它发生在主干与SGER分支从零、同学习率联合训练的条件下。

对话中检查过的另一轮全阶段checkpoint没有记录在Word文档中，不纳入本文结果。本文所有DTU指标均按官方含义解释：`acc`、`comp`和`overall`都是**越低越好**。

### 2.2 实验10：多阶段refinement破坏级联搜索

实验10在训练后期的Stage3 gate约为0.238，残差幅度约为0.354–0.378，单看门控和残差并没有明显失控。但其DTU结果明显变差，说明问题不只在最终Stage3输出，而在于：

1. Stage1、Stage2也进行SGER修正；
2. refined depth参与下一阶段搜索范围构建；
3. 早期阶段的局部残差会改变后续深度假设中心；
4. 误差经过级联传播后，Stage3很难完全修复。

实验10证明：即使单个stage的gate均值不高，只要refined depth进入coarse-to-fine反馈链，SGER误差仍可能被逐级放大。因此后续不应恢复全阶段refinement，也不应让Stage3以前的SGER结果参与深度搜索。

### 2.3 实验11：保护了raw路径，但gate过度开放

实验11改为Stage3-only后，级联搜索不再受SGER干扰。其raw depth + raw confidence取得了实验11最佳结果，证明Stage3-only结构成功保护了CasMVSNet主干。

但实验11的`geometry_gate_mean`从Epoch 0的0.7151一直维持到Epoch 12的0.7205。SGER本应是稀疏、局部修正器，实际却在大范围像素上持续开放。虽然平均绝对残差从0.4229降到0.2814，大面积的小残差仍可能系统性破坏原本较好的raw depth。

### 2.4 实验12：深度监督恢复，但优化轨迹存在明显双稳态

实验12有两个截然不同的训练阶段：

- **Epoch 0–6：严重失稳。** `depth_loss≈79`、`abs_depth_error≈80`，2 mm错误率约0.989，几乎没有形成有效深度估计。
- **Epoch 9–15：突然恢复并继续改善。** Epoch 9的depth loss降到5.39，Epoch 15进一步降到4.66。

由于实验12没有冻结主干，且主干与SGER使用相同学习率，这种突变更像是从零联合训练中的优化双稳态：网络长时间停留在无效深度解，随后才跳入正常收敛区域。它说明当前“raw主干、normal head、gate、residual head同时从零竞争”的目标耦合过强，训练结果可能对随机种子、batch顺序和学习率轨迹敏感。

更重要的是，gate行为与设计目标相反：

```text
Epoch 0: gate = 0.161
Epoch 6: gate = 0.183
Epoch 9: gate = 0.745
Epoch 15: gate = 0.750
```

实验12初期gate处于期望的局部范围，但当深度主干开始有效收敛时，gate迅速饱和到约0.75。新增的：

```text
L_gate = mean(geometry_gate)
gate_loss_weight = 0.001
```

没有在有效训练阶段抑制gate。其原因很可能是：

- `0.001 × gate_mean`对总loss的贡献只有约`0.00075`，而总loss仍为26–31，量级过小；
- 单纯最小化gate均值只表达“越小越好”，没有定义合理的目标占空比；
- refined depth监督可能通过打开gate获得更直接的优化通路，其梯度压过稀疏项；
- sigmoid gate接近高值后梯度减弱，进一步增加回落难度。

因此，实验12验证了“小残差上限 + 很弱的gate均值惩罚”不足以构成可靠的局部门控。

实验11和实验12的字母含义为：

- b：refined depth + residual-calibrated confidence；
- c：raw depth + raw photometric confidence。

实验12文档没有记录a组，因此不能直接分离“refined depth本身”和“softened calibration”各自的影响。

### 3.2 实验10相对baseline全面退化

实验10 Epoch 15相对baseline：

```text
acc:     +0.0271
comp:    +0.0231
overall: +0.0251
```

三个指标全部变差，且点数反而增加0.65%。这说明问题不是过滤过强，而是全阶段refinement生成了更多但几何质量更差的点。该结果支持彻底放弃多阶段SGER反馈。

### 3.3 实验11最佳结果来自raw路径

实验11-c Epoch 14达到：

```text
acc=0.2939
comp=0.3524
overall=0.3232
```

它优于baseline，也明显优于实验11-a和实验11-b。由此可以拆分出两个结论：

1. Stage3-only训练没有破坏raw backbone，甚至让raw结果达到较好水平；
2. 当前SGER refinement对最终深度是负贡献。

实验11-b虽然acc降到0.2481，但comp恶化到0.5003。这不是综合质量提升，而是强残差置信度过滤保留了少量高精度点、牺牲了大量表面覆盖。

### 3.4 实验12改善了acc，但牺牲了comp

实验12-c Epoch 15相对baseline Epoch 15：

```text
acc:     -0.0133  （改善）
comp:    +0.0077  （变差）
overall: -0.0028  （小幅改善）
```

实验12 raw backbone具有更好的点精度，但覆盖完整性下降。与实验11-c最佳结果比较：

```text
实验12-c acc:     再改善0.0057
实验12-c comp:    恶化0.0122
实验12-c overall: 恶化0.0032
```

因此实验12不是简单失败，而是把误差权衡从“均衡”推向“更准但更不完整”。它说明新损失确实改变了主干学习，但没有带来更好的acc/comp平衡。

实验12-b Epoch 15相对实验12-c：

```text
acc:     恶化0.0138
comp:    改善0.0024
overall: 恶化0.0057
```

softened calibration不再像实验11-b那样极端删除点，但refined + calibrated仍没有超过raw + raw。当前证据仍不能证明SGER输出具有正向价值。

### 4.2 置信度校准行为发生了根本变化

实验11-b比baseline少约21%的点，和其极差的comp完全一致。旧校准公式过于激进。

实验12-b点数却接近甚至略高于baseline，说明加入`alpha=0.25`和`floor=0.5`后，残差校准已经不再是强过滤器。它缓解了实验11的点云坍缩，但没有改善overall。这说明：

- 实验11-b的问题主要是置信度过滤过强；
- 实验12-b的主要矛盾已经转为refined + calibrated组合质量不足；由于缺少a组，暂时不能把责任完全归因于refined depth或calibration中的某一个；
- 继续调confidence公式无法替代对refinement本身的修复。

### 4.3 实验12-c的完整性问题集中在几何一致性

实验12-c使用raw confidence，却仍比baseline少约3%的点。尤其Scan49：

```text
Baseline Epoch 15: 4,666,372
实验12-c Epoch 15: 4,306,040
```

减少约36万点。由于没有使用calibrated confidence，这一损失更可能来自raw depth改变后，多视图几何一致性筛选未通过，而不是置信度阈值直接删点。下一轮必须按scene记录：

- photometric mask通过率；
- geometric consistency mask通过率；
- 每个view-consistency计数分布；
- raw/refined深度在Scan49上的误差和有效点分布。

## 5. 实验10、11、12的阶段性结论

### 5.1 实验10

- 全阶段SGER和refined feedback方向不可取；
- gate均值不高也不能避免级联误差传播；
- 更多点数没有转化为更好acc或comp；
- 后续保持Stage3-only，不恢复Stage1/Stage2 SGER。

### 5.2 实验11

- Stage3-only成功保护raw backbone；
- raw + raw是最佳设置，refinement没有产生稳定正贡献；
- gate约0.72，作用范围过大；
- 旧calibrated confidence过度过滤，不能作为默认结果。

### 5.3 实验12

- 从零联合训练存在严重早期失稳，稳定性不足；
- residual上限从0.5降到0.25后，仍未解决gate后期饱和；
- `gate_loss_weight=0.001`实际约束强度不足；
- raw acc继续改善，但comp下降，overall未超过实验11-c；
- softened confidence解决了“删点过多”，但refined + calibrated组合仍未超过raw + raw；由于缺少a组，refined与calibration的独立贡献尚不能分离；
- 实验12没有记录mean absolute residual和refined + raw confidence，这是判断safe-refine及校准贡献的关键证据缺口。

## 6. 下一步 SGER-CasMVSNet 具体优化方向

下一步不应增加SGER层数、扩大残差范围或恢复多阶段refinement。优先目标应从“增强细化能力”改为：

```text
先保证从零训练稳定
→ 再保证gate只在有真实改善的位置开放
→ 再保证residual方向和幅度正确
→ 最后才校准融合置信度
```

### P0：解耦从零训练中的主干与refiner竞争

#### 方向1：refinement强度渐进启用

保持所有实验从零训练，不冻结backbone，但引入epoch相关的SGER系数：

```text
depth_refined = depth_raw + beta(epoch) * gate * residual
```

推荐初值：

```text
Epoch 0–2: beta = 0
Epoch 3–5: beta从0线性升到1
Epoch 6以后: beta = 1
```

Epoch 0–2期间NormalHead和SGER仍可前向并记录指标，但refined depth不反向扰动深度主干。这样符合“全部从零训练”的实验协议，又避免随机refiner在主干尚未形成有效深度时参与竞争。

继续条件：

- Epoch 0–3的depth loss进入与实验8/11相近量级；
- 不再出现连续多个评估点`abs_depth_error≈80`；
- raw depth训练曲线对随机种子稳定。

#### 方向2：降低早期refined监督权重

当前Stage3同时使用：

```text
1.0 × raw depth loss + 1.0 × refined depth loss
```

建议配合beta采用：

```text
Epoch 0–2: refined_depth_loss_weight = 0
Epoch 3–5: 从0线性升到0.5
Epoch 6以后: 0.5
raw_depth_loss_weight始终为1.0
```

先不要恢复到1.0。refined loss通过`depth_refined = depth_raw + residual`也会向raw主干传播，权重1.0等价于在Stage3显著加强主干监督，并混入不稳定的residual梯度。

### P1：把gate从“均值越小越好”改为“有预算、有收益才开放”

#### 方向1：目标占空比约束

用目标区间代替简单的`mean(gate)`：

```text
g = valid区域内的mean(gate)
L_gate_budget = relu(g - g_max)^2 + relu(g_min - g)^2
```

推荐：

```text
g_min = 0.10
g_max = 0.30
gate_budget_loss_weight = 0.01
```

这样既避免gate塌缩到0，也避免重新升到0.75。初始权重0.01是当前0.001的10倍，但仍需根据实际梯度范数调整，而不是只比较loss标量。

必须新增日志：

```text
stage3/gate_budget_loss
stage3/gate_above_max_ratio
stage3/gate_below_min_ratio
stage3/gate_grad_norm
stage3/residual_grad_norm
```

#### 方向2：改善感知的gate监督

训练时利用GT构造“该残差提议是否真的改善raw depth”的标签。先让ResidualHead输出未门控提议：

```text
depth_proposal = depth_raw.detach() + raw_residual
improved = |depth_proposal - GT| + tau < |depth_raw.detach() - GT|
```

然后：

```text
L_gate_improve = BCE(gate, improved)
```

推荐初值：

```text
tau = 0.1 × 当前stage depth interval
gate_improve_loss_weight = 0.05
```

这比`mean(gate)`更直接：gate不是无条件稀疏，而是只在residual提议具有可验证收益时开放。`improved`必须停止梯度，避免模型通过操纵标签降低损失。

### P2：直接监督residual方向，而不只惩罚其幅度

当前residual loss主要限制幅度，safe-refine只在最终refined比raw差时惩罚，但两者都没有明确告诉ResidualHead正确修正方向。

建议构造有界残差目标：

```text
r_target = clamp(
    GT - depth_raw.detach(),
    -0.25 × depth_interval,
    +0.25 × depth_interval)

L_residual_target = SmoothL1(raw_residual, r_target)
```

推荐：

```text
residual_target_loss_weight = 0.05
原residual_loss_weight从0.01降到0.005
safe_refine_loss_weight保留0.1
```

目标监督只在有效GT区域计算。它解决“残差应该往哪个方向走”，gate负责“哪里应该使用残差”，两者职责分离。

如果direct residual target导致所有像素都尝试修正，则只在以下区域启用：

- raw误差大于`0.25 × depth_interval`；
- photometric confidence高于阈值；
- 非明显图像边缘；
- 或由改善感知标签筛选。

### P3：延后confidence calibration优化

实验12已经证明softened calibration不会再造成21%的点云坍缩，但它仍没有超过raw + raw。现阶段应：

1. 默认报告raw + raw；
2. 必须补齐refined + raw；
3. 只有当refined + raw稳定优于raw + raw后，才继续优化calibrated confidence。

后续不要仅用residual幅度代表不确定性。残差大可能意味着网络成功纠正了大误差，并不必然低可信。可改为学习：

```text
target_confidence =
exp(-|depth_refined.detach() - GT| / tau_depth)
```

或者直接预测：

```text
P(|depth_refined - GT| < threshold)
```

但该方向应排在gate和residual质量之后。

### P4：补齐诊断输出和固定评估协议

下一轮每个checkpoint必须记录：

```text
stage3/raw_abs_error
stage3/refined_abs_error
stage3/raw_to_refined_error_delta
stage3/refined_improved_pixel_ratio
stage3/mean_abs_depth_residual
stage3/geometry_gate_mean
stage3/gate_on_improved_ratio
stage3/gate_on_worsened_ratio
```

每个checkpoint必须导出：

```text
A: raw depth + raw confidence
B: refined depth + raw confidence
C: refined depth + calibrated confidence
```

同时记录每个scene的点数、photometric mask通过率和geometric mask通过率。checkpoint选择以DTU overall为准，不以训练depth loss为准。

## 7. 推荐的下一轮最小消融矩阵

为避免多个改动再次无法归因，建议按以下顺序，每组仅增加一个变量：

| 组别 | 改动 | 目的 | 进入下一组的条件 |
|---|---|---|---|
| A | Stage3-only + gate低占空比初始化 | 检查gate初值是否能保持 | gate不在Epoch 9后跳到0.7以上 |
| B | A + beta/refined-loss warm-up | 解决从零训练早期失稳 | Epoch 0–3不再出现深度误差约80 |
| C | B + gate target budget | 将gate稳定在0.10–0.30 | gate稳定且refined不明显劣于raw |
| D | C + residual target supervision | 学习正确修正方向 | raw-to-refined delta为正 |
| E | D + improvement-aware gate | 只在真实改善区域开放 | gate_on_improved显著高于gate_on_worsened |
| F | E + learned/validated calibration | 改善融合acc/comp平衡 | calibrated overall优于refined+raw |

所有组都应从零训练，使用相同随机种子、训练轮数、数据划分、`ndepths`、`depth_inter_r`和`dlossw`。为判断稳定性，关键组B、C、D至少增加两个随机种子复验。

## 8. 最终判断

实验10到实验12逐步排除了三个问题：

1. **实验10排除多阶段SGER反馈。** 它会破坏级联搜索，导致acc和comp全面下降。
2. **实验11确认Stage3-only方向正确。** raw backbone得到保护，但refinement和旧confidence calibration无效。
3. **实验12确认仅缩小残差并加入弱gate惩罚仍不够。** raw acc有所提升，softened confidence不再大量删点，但从零训练早期严重失稳，gate后期重新饱和，refined + calibrated组合仍未超过raw + raw。

下一步最重要的不是继续调整`0.25`到更小，也不是增加SGER容量，而是把SGER改造成一个职责明确的条件修正器：

```text
ResidualHead提出有方向监督的局部修正
→ Gate只在该修正确实可能改善raw depth时开放
→ 训练早期通过渐进启用避免扰动从零学习的主干
→ refined稳定优于raw后，再学习融合置信度
```

在这一条件满足前，正式结果仍应以：

```text
raw depth + raw photometric confidence
```

作为默认输出。
