# 实验15-C门控专项审计分析

研究主体：SGER-CasMVSNet（自几何与边缘细化残差-CasMVSNet网络）。本次分析 gate_audit_15b_epoch9.json、gate_audit_15b_epoch12.json、gate_audit_15b_epoch15.json；不修改网络或损失。

三个报告均为当前代码加载对应15-B checkpoint，checkpoint_epoch与audit_epoch匹配，无missing/unexpected keys；同一训练首Batch、batch_size=2、seed=1、GT有效像素487128、主干未冻结。各组梯度均有限。统计为full_schedule的Stage3有效GT像素合并统计，非验证集汇总。当前代码已有梯度隔离，不能据此复原历史计算图。

## 1. Epoch9/12提案是常数，不只是偏小

Epoch9的raw_residual在所有有效像素上min=max=mean=0.0019200121；Epoch12为0.0015241571。它们都是正数，没有空间变化。

residual_target_only反传中，两个checkpoint的residual body均为6/6参数张量零梯度；output层2个张量中有1个零梯度，联合范数分别0.1303047和0.0253773。因此此前“残差目标仍能驱动提案”的表述必须细化：输出层仍有更新信号，但不能证明残差主体可以学习。

这与输出退化到偏置主导、上游ReLU失活等机制相容，但报告未采集中间激活或逐参数梯度，不能断言非零梯度一定属于bias，也不能将dead ReLU定为已证实根因。Epoch15主体梯度恢复至0.4380995，6个张量均非零，提案范围恢复到[-0.659048,0.129787]。

## 2. 全负收益标签的充分原因已明确

三个checkpoint的benefit_margin均为0.13180958。Epoch9/12的最大提案收益仅0.00192261、0.00152588，远低于margin；提案幅度分别比门槛小约69、86倍。

由绝对误差的三角不等式，误差下降不可能超过修正幅度。因此在本Batch下，即使方向正确，这种幅度的提案也不能成为正标签。实际仍有142736、222487个像素获得微小正收益，但全部低于margin；target_positive、predicted_positive和true_positive均为0。

这不意味着现有margin应直接降低：幅度差来自接近常数的小提案，应先解释提案退化。Epoch15已有114466个目标正样本，说明该门槛并非对所有模型状态都不可达。

## 3. 两个学习门控分支均极端负饱和，几何权重并未同步关闭

在各自活动区域内，Gate A logits中位数：Epoch9=-51.6708、Epoch12=-54.6305；Gate B为-58.8341、-63.1272。两个分支sigmoid都接近0。

相比之下，B区域几何权重中位数分别0.456265、0.456208、0.456373，跨三个checkpoint基本稳定；A区域权重恒为1。因此最终门控关闭的主要可见因素是学习分支输出，不是几何权重整体归零。

Epoch9/12最终门控最大值仅1.8523e-8、4.9965e-8，全部487128个有效像素均低于1e-6。models/module.py中的BCE输入clamp在该区间梯度为0，因此本Batch的收益门控监督被全部硬截断；与gate_benefit_only所有SGER梯度为0一致。两个报告中的fatal error即该零梯度诊断，不是主干泄漏。

需要区分截断与关门的起因：全负标签本来就监督关门；clamp使当前监督梯度归零，但不能证明它最初造成了负饱和。仅改稳定BCE也不会在全负标签条件下产生开门监督。

## 4. Stage3几何边界得到有效补充验证

所有三个checkpoint的4项Stage3几何独立损失Backbone梯度均为0。

Epoch15四项损失的SGER梯度范数分别为：normal smooth 0.1036281、curvature 0.0014280、edge smooth 4.18934e-5、depth-normal 0.5177173，均有限且非零。结合此前核心SGER损失和已激活safe-refine的结果，当前代码在该Batch下未发现SGER到主干泄漏。

Epoch9/12的平滑、曲率和边缘平滑到SGER的梯度极小，不能把“隔离正确”与“SGER学习正常”混为一谈。

## 5. Epoch15恢复，但收益选择仍不充分

最终门控低于1e-6比例为0，最大值0.998872；B活动区域sigmoid中位数0.7730，但最终门控中位数0.2550，说明几何权重仍对门控产生明显影响。

正收益提案278736个，其中164270个未达到margin；目标正样本114466、预测正样本77504、真阳性33283。precision=42.94%、recall=29.08%。这个目标衡量未门控提案能否超过收益门槛，不能与最终细化改善像素比例混用。

本Batch平均未门控提案收益0.045868，实际门控细化收益约0.024015。门控降低了平均修正幅度，也降低了该Batch的平均收益；仅此不能证明门控总体有害，因为尚未比较尾部误差、跨Batch稳定性和重建结果。最终raw误差2.509561、refined误差2.485546，仍有小幅正贡献，但未达到稳定研究贡献标准。

## 6. 下一步优先级更新

新增证据表明，优先级应从“只查门控clamp”调整为“先定位残差主体为何退化为常数，同时保留门控数值问题的独立验证”。

1. 在Epoch9/12/15上采集ResidualDepthHead各Conv/ReLU前后激活分布、正激活比例、最后一层输入空间方差，以及output.weight/output.bias各自梯度。检查常数是否等于max_residual*tanh(output.bias)。只读审计，不更新参数。
2. 在多个固定Batch复核；当前三个文件仍是同一首Batch，不代表已完成多Batch验证。区分整个分支失活与特定Batch触发。
3. 若确认残差主体ReLU失活，围绕该已证实机制做单变量修改，保持门控、权重和margin不变以便归因；若主体正常，再调查权重、连接和提案监督。门控硬clamp数值修正作为另一独立变量验证，不能一次同时修改。
4. 在正/负目标、极端logits、双区域几何权重下测试稳定门控损失，保持实际概率组合语义；不要把最终门控概率直接当logit传给BCEWithLogitsLoss。

当前不建议直接提高Residual Target权重：主体反传为零时，乘大权重仍不能让该主体恢复梯度。也不应强行开Gate、直接降低收益门槛或同时更改多个因素。
