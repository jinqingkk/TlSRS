# 实验15-C第一阶段：单 Batch 梯度审计

本实现用于 SGER-CasMVSNet（自几何与边缘细化残差-CasMVSNet网络）的优化边界诊断，不执行 optimizer.step，不写入输入 checkpoint，不启动完整训练。

## 源码状态

当前活动链为 models/cas_mvsnet.py → models/module.py 和 models/sger_refinement.py。当前 SGER-Lite 已隔离最终阶段的 reference feature、raw depth、confidence、uncertainty、NormalHead 输入和 refined 加法基础深度。本次未修改网络或训练损失。审计当前源码不能重建实验15-B历史梯度路径，即使加载15-B权重也不能将结果解释为历史代码的证据。

## 运行

```bash
python gradient_audit.py \
  --trainpath ./data/DTU/mvs_training/dtu/ \
  --trainlist lists/dtu/train.txt \
  --loadckpt ./checkpoints/experiment15_b_backbone_lr1/model_000015.ckpt \
  --audit_epoch 15 \
  --batch_size 2 \
  --seed 1 \
  --freeze_backbone_epochs 0 \
  --backbone_lr_scale 0.1 \
  --output_json outputs/experiment15_c/audit_15b_epoch15.json
```
```bash
 python gradient_audit.py \
  --trainpath ./data/DTU/mvs_training/dtu/ \
  --trainlist lists/dtu/train.txt \
  --loadckpt ./checkpoints/experiment15_b_backbone_lr1/model_000009.ckpt \
  --audit_epoch 9 \
  --batch_size 2 \
  --seed 1 \
  --freeze_backbone_epochs 0 \
  --backbone_lr_scale 0.1 \
  --output_json outputs/experiment15_c/gate_audit_15b_epoch9.json
```


默认随机初始化，种子1。诊断历史权重可附加 `--loadckpt /path/to/model.ckpt`；仅载入模型，不恢复优化器。audit_epoch 为零基调度编号，应明确填写，不能从文件名推断。单 Batch 可以含多个样本；固定读取训练数据集首批，shuffle=False，num_workers=0。

独立审计 raw、refined、residual target、gate benefit、safe-refine、normal smooth、curvature、edge smooth、depth-normal。另保留 full_schedule 和 full_forced。独立项权重为1且调度强制激活，用于测试路径；full_schedule 记录配置权重和实际调度。独立项通过浅拷贝 stage 输入消除原损失中 Stage1/2 无条件深度监督的干扰，不修改前向张量连接。

几何独立项保留所有 stage，反映当前训练中的几何损失，包括允许更新 raw 主干的粗阶段几何项；不能把这些汇总的 backbone 梯度直接认定为 SGER 泄漏。normal_smooth 是现有深度平滑函数，并非直接监督 NormalHead；depth_normal 才使用预测法线。

## 报告解释

每项 gradient_summary 提供 backbone、feature_net、cost_reg_net、normal_head、residual_head、benefit_gate 和 sger 梯度 L2 范数。backbone 是 FeatureNet 与 CostRegNet 参数梯度的联合 L2；sger 包含最终 NormalHead、SGER特征投影、残差和门控。比值为 backbone/sger，分母为零记 null。

四个 SGER 专属损失以 backbone > 1e-8 标记 backbone_leak_detected；发现泄漏是诊断结果，不自动启动隔离训练。非有限梯度时不作边界结论。parameter_gradients 区分缺失梯度、全零梯度、冻结参数、非有限值和优化器遗漏。safe-refine 为零时注明 hinge 未激活；零初始化的残差输出也可能使上游或门控梯度为零，不能仅据此判定塌缩。冻结主干时零梯度不能证明结构隔离，应以 freeze_backbone_epochs=0 审计。

每个 case 前恢复参数与 BatchNorm 缓冲区并清空全部参数梯度；结束恢复模型状态和 residual scale。JSON 记录完整参数、数据路径、批次选择、种子、PyTorch版本、checkpoint及其epoch、实际调度和损失权重。输出的优化器覆盖是本次重建优化器的覆盖，不代表历史优化器状态。

## 2026-09-08：门控专项诊断扩展

已在审计入口加入只读forward hooks，不修改网络、损失或checkpoint格式。原有命令即可启用，建议输出到新的文件（例如 `outputs/experiment15_c/gate_audit_15b_epoch12.json`），保留旧报告。

每个case的 `loss_extras.gate_diagnostics.stage3` 包含：

- `distributions`：Gate A/B logits、sigmoid、A区域指示权重、B几何权重、最终门控、残差提案及绝对值、有效残差、提案收益、benefit margin、收益减margin。各项记录count、finite_count、nonfinite_count、min/p01/p05/p50/p95/p99/max/mean；精确分位数在CPU上计算。
- `region_distributions.a/b`：对应分支区域内的logits、sigmoid、几何权重及最终门控分布，用于区分不活动区域与分支饱和。
- 最终门控低于1e-6、超过1-1e-6的数量和比例；严格不等号对应BCE前clamp的区间外部分。
- target_positive_count、predicted_positive_count（门控>=0.5）、true_positive_count，以及positive_gain_count、positive_gain_below_margin_count。收益标签直接复用生产函数，保持浮点运算顺序。

统计使用各stage的GT mask>0.5，跨Batch像素合并，不是逐图均值。空集合的统计值为null；分位数剔除非有限值并记录其数量。GT只用于审计统计，不进入模型输入。A几何权重为区域指示值，不是学习概率。

新增 `stage3_normal_smooth_only`、`stage3_curvature_only`、`stage3_edge_smooth_only`、`stage3_depth_normal_only` 四组，仅将stage3传入原损失；保留原有stage衰减（stage3为1/4），原基础权重设为1，raw/refined深度监督权重为0。对应gradient_summary按SGER专属损失报告主干泄漏。当前该组要求存在stage3的SGER输出。

console已调整为先显示case名称，再显示该case的gradient_summary，避免与上一组误配。

验证：tests/test_gate_audit.py 检查hook前向/梯度等价与异常清理、标签计数、空掩码/非有限值、Stage3独立几何反传；原审计测试继续使用。新增指标尚未在真实DTU checkpoint上运行；现有JSON不会自动增加这些字段。

补充验证：完整CascadeMVSNet在train模式、合成Batch=2、32×32图像、8/8/8深度采样下，已通过hook到stage输出的映射、JSON序列化和四项Stage3几何损失独立backward；FeatureNet/CostRegNet梯度均为零。尝试eval模式反传时，旧模型的原地cost volume运算触发autograd版本错误；因此本审计保持train模式，不宣称支持eval模式梯度审计。


## 2026-09-10：残差主体专项审计与固定多Batch扩展

已实现 `residual_audit_utils.py`，由现有入口自动启用。未修改生产网络、损失、门控或训练调度。

每个case新增：

- `loss_extras.residual_diagnostics.stage3.activations`：ResidualDepthHead每层Conv/ReLU的input/output统计，包含有限值分位数、正值/零值比例、形状及逐样本逐通道空间总体方差的分布。统计覆盖全部B,C,H,W，不使用GT掩码；非有限值单独计数，空统计为null。ReLU输入在pre-hook内即时统计，避免原地ReLU覆盖负值。
- `bias_only_expected_proposal`：按生产stage interval计算 `max_residual_ratio * depth_interval * tanh(output.bias)`。
- `abs_proposal_minus_bias_only`：实际未门控提案与上述偏置提案的绝对差分布；这两项使用Stage3 GT有效掩码。相等不能单独证明ReLU失活，输出权重为零也能产生此结果。
- `residual_parameter_gradients`：按模块名及完整残差参数名报告梯度，分别包含output.weight/output.bias和每层body参数；区分无梯度、零梯度、非有限值、requires_grad和当前优化器覆盖。该字段在backward后采集。

新参数 `--batch_indices` 为逗号分隔的零基Batch编号，默认 `0`，保持单Batch文件结构兼容。多Batch时输出名附加 `_batch0000` 等后缀，不生成无后缀的汇总文件。每份报告记录batch_index、精确dataset_indices、可用的dataset.metas及train模式；每批均重新恢复同一模型参数和BN状态，各case也独立恢复。不同checkpoint使用完全相同的数据配置、batch_size和batch_indices。选前5批不等于跨场景代表性采样，可指定分散的固定编号。

示例（Epoch9；Epoch12/15分别替换checkpoint、audit_epoch与输出文件名）：

```bash
python gradient_audit.py \
  --trainpath ./data/DTU/mvs_training/dtu/ \
  --trainlist lists/dtu/train.txt \
  --loadckpt ./checkpoints/experiment15_b_backbone_lr1/model_000015.ckpt \
  --audit_epoch 15 --batch_size 2 --seed 1 \
  --batch_indices 0,1,2,3,4 \
  --freeze_backbone_epochs 0 --backbone_lr_scale 0.1 \
  --output_json outputs/experiment15_c/residual_audit_15b_epoch15.json
```

检测到门控关键梯度缺失等诊断错误时，仍保存报告并继续剩余Batch，最终退出码为1；运行异常仍直接报错。默认train模式，不提供eval反传支持。逐层精确分位数会增加CPU统计时间，入口逐批打印进度。审计不执行optimizer.step，不改写输入checkpoint。
