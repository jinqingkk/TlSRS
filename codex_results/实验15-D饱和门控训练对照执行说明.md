# 实验15-D：Epoch12饱和门控训练对照

日期：2026-09-26。研究主体：SGER-CasMVSNet（自几何与边缘细化残差-CasMVSNet网络）。遵循[项目规则](../project_rules/SGER_RULES.md)。

## 本轮范围

承接15-D已完成的BCE机制审计、Epoch15冻结200步对照及Epoch12残差恢复诊断。本轮补充“固定LeakyReLU且有收益正标签时，稳定BCE是否恢复饱和门控训练”的缺项。此前正负平衡25步主要缩小残差，不能作为已恢复方向的模型。本轮不采用该平衡损失，不以强制开门或降低margin制造收益。

新增入口 `experiment15_d_bce_pressure.py`。生产网络、损失函数、历史实验入口保持原样。加载原两步恢复目录的 `leaky_relu/step_0001.ckpt`，即epoch12权重已经过一次激活恢复更新；不是15-B原始epoch12快照，也不是新网络从零训练。

三组：`legacy_reference`、`legacy_repeat`、`stable`。唯一组间因素是 `legacy_clamp` / `stable_logprob`。共同固定LeakyReLU(0.01)、原像素均值残差目标监督、全部损失权重、margin、范围、种子和样本。完整恢复Adam，两个参数组保存lr均为0.00025，无scheduler。冻结主干参数、BN及优化器状态，SGER及末级法线头可训练；验证全模型eval后恢复BN/RNG。

## 执行与检查

先运行2步三组对照，检查通过后独立运行25步；25步重新从共同起点开始，前两步重复验证，不从任一组末尾继续。沿用原样本清单[2:52]，2步取前4条；固定scan3/5/17的6个验证样本。节点0、1、2、5、10、25（不超过指定步数）。

```bash
CUBLAS_WORKSPACE_CONFIG=:4096:8 OMP_NUM_THREADS=1 PYTHONPATH=. python -u experiment15_d_bce_pressure.py \
  --probe_dir outputs/experiment15_residual_recovery/probe_2steps_epoch12_20260920_214234_152286 \
  --steps 2 --strict_determinism
```

两步检查通过后，同命令将 `--steps 2` 改为 `--steps 25`。新输出目录自动创建于 `outputs/experiment15_d/bce_pressure_*`；不覆盖历史结果。不自动扩展到正式训练。

每组第一个实际训练前向必须存在饱和收益正标签（GT有效、gate<1e-6且提案改善超过margin）。使用实际有效权重单独计算BCE对活动logit的梯度：旧BCE对应梯度须全零，稳定BCE须全部为有限负值。只做autograd.grad，不额外更新参数；完整训练仍使用原生产损失总和。

每步检查完整参数/梯度有限性、主干冻结、raw/置信度保护和SGER实际更新；逐组初始模型/优化器须相同，step0验证和首步前向除loss外须相同，旧BCE重复组全轨迹精确相同。验证不改变模型、优化器、BN或RNG。输入快照和清单保存哈希，结束检查未改变。

`gate_pressure`记录饱和像素、饱和收益正标签数量、该区域raw-refined误差差值之和及训练时专属BCE梯度方向计数。验证的饱和区域随模型变化，不是固定初始像素的纵向跟踪。`signed`记录正负零目标的提案符号统计。验证深度指标按有效像素加权，门控precision/recall按汇总计数计算，分母0记null。各组loss因BCE实现不同不直接用于质量排名。

## 判定

检查通过仅证明对照有效。必须分别报告：数值梯度恢复、门控参数/输出恢复、未门控提案收益、最终refined收益。平均提案收益为负不排除门控选择局部有益提案的可能，是否成功由固定验证raw/refined决定。

若25步门控恢复且refined持续优于raw，才考虑更长验证；若打开后恶化，优先处理选择性与残差方向；若仍接近零，结合logit变化判断恢复速度，不宣称模型成功。该压力实验不能证明原ReLU架构只改BCE的精度收益。尚需正式训练、激活/BCE消融和同raw confidence的DTU公平重建评估。

### 2026-09-27代码补充：门控恢复速度诊断

在上述方案记录之后，补充了独立实验入口`experiment15_d_bce_pressure.py`的诊断输出，生产网络、损失公式和实验超参数不变：

- 每次训练更新前后及验证记录有效区域、当前饱和区域、当前饱和收益正标签区域的活动logit和最终gate统计：像素数、总和、均值、最小值、最大值。空区域的均值和极值为null，不记为0。
- 活动logit按区域选择A/B分支；最终gate还包含几何权重，不能将gate变化全部解释为logit变化。诊断张量detach，不参与损失或参数更新。
- 验证汇总增加`gate_logits`和`gate_logits_scenes`，按像素计数汇总，避免对不同大小区域的batch均值直接平均；增加`signed_scenes`以检查各场景正负方向表现。
- 每次前向记录`effective_gate_benefit_weight`，验证日志直接显示有效区域平均logit与gate，便于观察门控接近零时是否仍在变化。

逐batch字段位于`gate_pressure.logits`。饱和区域和收益正标签区域均按当前输出重新计算；跨节点均值变化包含区域成员变化，不能解释为同一批像素的逐点恢复。固定验证样本的有效GT区域统计可辅助判断整体变化。
