# SGER残差提案退化研究步骤

日期：2026-09-19。

研究主体：**SGER-CasMVSNet（自几何与边缘细化残差-CasMVSNet网络）**。

本文为待执行的研究方案，目标是恢复SGER残差主体的有效学习，使其生成方向正确、有实际细化收益的残差提案。本文整理研究步骤，不代表已完成新增代码或实验。项目约束遵循[SGER_RULES.md](../project_rules/SGER_RULES.md)。

## 1. 现有证据与待验证假设

依据[早期checkpoint筛选结论](实验15-D早期checkpoint筛选结论.md)，Epoch9/12在已审计的ReLU配置和样本上有以下现象：

- 残差提案与bias-only输出完全一致，缺少可观察的输入相关变化。
- 提案绝对值约为0.0019和0.0015，远小于约0.1318的收益margin，收益正标签为0。
- 门控严重接近零，但在没有收益正标签的情况下，单独修复BCE梯度不构成鼓励开门的监督。
- 改用末端LeakyReLU(0.01)的压力组产生了不同的提案和收益正标签，支持优先检查末端激活通路。

这些证据不证明全部问题由ReLU导致，也不代表所有数据和后续训练状态都如此。

按顺序验证两个假设：

1. **学习通路假设：**末端ReLU把输入相关特征清零，使残差主体梯度受阻、输出退化为偏置主导。
2. **有效修正假设：**恢复主体学习通路后，提案能够学习正确方向并降低深度误差，而不只是幅度或空间变化增大。

## 2. 第一步：定位退化位置

### 2.1 先复核已有审计

优先读取Epoch12的逐层激活、残差主体梯度和末端激活A/B记录，以Epoch9作为复核点。已有指标完整时直接使用；只有缺项或运行条件改变时才补充审计。

参考资料：

- [残差主体多Batch审计分析](实验15-C残差主体多Batch审计分析.md)。
- [末端激活AB审计结果分析](实验15-C末端激活AB审计结果分析.md)。
- [门控BCE数值稳定性AB审计结果分析](实验15-D门控BCE数值稳定性AB审计结果分析.md)。
- 原始记录：`outputs/experiment15_d/audit_relu/`、`outputs/experiment15_d/audit_leaky_relu/`。

确认活动导入链为 `models/cas_mvsnet.py` → `models/module.py`、`models/sger_refinement.py`，避免误读备用实现。

### 2.2 检查前向通路

| 检查位置 | 记录指标 | 要回答的问题 |
|---|---|---|
| 末端ReLU之前 | 正值比例、均值、分位数、空间方差 | 输入是否主要落在负半轴？是否仍含空间信息？ |
| 末端ReLU之后 | 零值比例、空间方差 | 输入相关特征是否被清零？ |
| 残差输出层 | 权重贡献、偏置贡献、提案与bias-only输出之差 | 为什么输出只剩偏置？ |
| 限幅及尺度变换 | 变换前后分布、饱和比例、实际尺度 | 是否还存在限幅饱和或调度缩小的影响？ |
| 最终细化 | 提案、门控、有效残差的逐像素关系 | 微小修正来自提案、门控还是两者共同作用？ |

bias-only对照应经过与真实输出相同的限幅、单位和尺度变换。激活分布标明是否统计全部B/C/H/W元素；深度质量指标只在对应stage的GT有效掩码上统计，不能混用口径。

### 2.3 分别检查损失与梯度

在同一checkpoint、相同batch和相同运行状态下，分别审计：

1. 残差目标损失单独反向。
2. refined深度损失单独反向。
3. 完整训练损失反向。

逐层记录参数梯度的None、全零、非零、非有限状态，以及梯度范数、优化器覆盖和期望更新边界。记录实际损失权重与调度尺度；专属损失的强制激活审计必须与实际训练权重下的结果分开报告。

重点检查残差目标损失是否直接监督未门控提案，以及这条通路是否被意外detach、无效掩码、零权重或激活阻断。门控接近零时，refined深度损失梯度弱不等于残差目标监督也应失效。

梯度审计不执行optimizer.step，不改写输入checkpoint。每个case应重置或恢复模型、BN与随机状态，避免运行先后污染比较。

### 2.4 第一阶段判定

- 若激活前存在变化、激活后全零，且残差目标损失无法传回主体，优先验证末端激活阻断假设。
- 若激活后仍有变化但输出权重贡献接近零，继续检查输出层权重、限幅导数及优化器状态。
- 若残差目标损失本身不生效，先修复监督连接、掩码或调度问题，另立单变量记录，不能直接归因于激活。
- 若单项损失能训练主体，但完整损失表现异常，再检查各项梯度尺度和方向冲突。

## 3. 第二步：只改变末端激活，验证短程恢复

### 3.1 对照设计

优先使用已观察到退化的 `checkpoints/experiment15_b_backbone_lr1/model_000012.ckpt`。这是恢复实验的起点，不预先认定其为最佳模型。

| 组别 | 残差末端激活 | 用途 |
|---|---|---|
| 基准组 | ReLU | 原配置对照 |
| 重复组 | ReLU | 检查可重复性 |
| 实验组 | LeakyReLU(0.01) | 检验负半轴学习通路恢复 |

三组固定同一BCE模式。建议沿用legacy_clamp以对应原配置；若另选模式，必须在执行前明确记录，并在三组中保持一致。此轮不同时更换BCE。

其余保持相同：初始化权重、恢复的优化器分组和动量、样本顺序、随机种子、学习率、损失权重、收益margin、残差范围及验证协议。不重置输出偏置，不同时放宽残差限幅或调低margin。

### 3.2 先两步，再决定是否200步

1. 补齐实验入口中的checkpoint和调度epoch配置。实际尺度按本轮明确选择的Epoch12调度记录，不能沿用写死的Epoch15设置。
2. 冻结主干参数并固定主干BN为eval；SGER及末级法线头保持train，验证后恢复这一模式。
3. 在冻结后的运行模式下重新检查初始激活与提案。历史train模式下的退化证据不能直接代替这一检查。
4. 做两步局部训练对照，核验同组重复一致、配对raw/置信度一致、主干参数和状态不变，以及SGER梯度和实际参数更新。
5. 若退化现象仍成立、实验组恢复预期通路且数值检查通过，再开展独立200步实验；第0、25、50、100、200步使用相同验证样本评估并保存快照。

两步和200步实验都涉及参数更新，应标注为局部训练对照，与无更新的梯度审计区分。冻结主干是诊断条件，不自动成为正式训练策略。

完整训练前应确认形状、有限性、残差上界、优化器覆盖及梯度路径。严格确定性或状态检查失败时，保留结果并定位，不能将“运行结束”等同于通过。

## 4. 第三步：判断恢复是否带来有效修正

定义raw深度为d，未门控提案为r，GT为g。提案收益为：

`proposal_gain = |d - g| - |d + r - g|`

正值表示未门控提案降低绝对误差。最终收益另用 `|d - g| - |depth_refined - g|` 衡量，不能用提案收益替代最终输出收益。

| 维度 | 必须记录的指标 | 判断目的 |
|---|---|---|
| 主体恢复 | 激活零值比例、空间方差、与bias-only输出差异、逐层梯度和参数变化 | 是否恢复输入相关学习 |
| 提案质量 | 残差目标误差、方向准确率、提案收益及其分布 | 是否学到正确修正方向 |
| 有益提案覆盖 | 超过收益margin的正标签数量和比例 | 是否形成可供门控学习的正监督 |
| 门控选择 | 门控均值、饱和比例、precision/recall、改善/恶化区域门控均值 | 是否选择了有益修正 |
| 最终细化 | raw/refined绝对误差、误差差值、改善/恶化像素比例、有效残差幅度 | 是否实际改善深度 |

记录训练/验证、stage、有效掩码、计数与聚合方式。验证误差按有效像素数加权，precision/recall按合并后的计数计算；空区域或分母为零时记null。方向准确率明确零提案和零GT误差如何计入，保持各组一致。

特别注意：在step0切换激活就可能改变提案，应分别报告“加载同一权重后的即时前向差异”和“继续训练后的变化”，不能把全部差异都称为学习恢复收益。

## 5. 根据结果选择后续研究

| 观察结果 | 下一步 |
|---|---|
| 主体梯度恢复，提案收益提高，refined也改善 | 进入更充分训练及公平raw/refined评估 |
| 主体和提案收益恢复，最终refined仍无改善，门控仍饱和 | 在固定激活下另做BCE/门控恢复单变量实验 |
| 提案变化增大，但方向错误或误差恶化 | 核对目标符号、单位、裁剪范围、输入几何线索及损失梯度冲突 |
| 切换激活后主体仍无有效梯度 | 继续定位监督连接、限幅饱和、掩码、调度或优化器覆盖 |
| 冻结后的初始模式不再出现退化 | 重新分析BN模式影响，不将历史现象强套到新实验 |

门控实验应在有益提案确实存在时进行。不得仅为了增加正标签而同时降低margin、扩大残差范围或强行打开门控。

## 6. 记录与最终验收

每轮保留假设、唯一主要改动、完整命令、源码和checkpoint哈希、恢复epoch、优化器及调度状态、样本清单、运行模式、实际权重和原始指标。三组使用独立目录，历史结果保持原样。

梯度恢复、提案变化和短程验证改善分别属于不同层次的证据，不能替代最终重建评估。正式贡献仍需同checkpoint、同raw confidence及相同融合协议比较raw/refined，报告逐场景和汇总Acc.、Comp.、Overall，并检查跨checkpoint或重复实验稳定性。
